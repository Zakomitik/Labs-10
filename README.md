# Учебный Python-проект для лабораторной работы № 2 по Git

Это очень простое консольное приложение на Python. Оно нужно для выполнения всех пяти заданий лабораторной: создание репозитория, приглашение соавтора, клонирование, commit/push/pull, ветки, merge и разрешение конфликта.

## Файлы проекта

- `main.py` — исходный код программы.
- `.gitignore` — исключает временные файлы Python и настройки редактора.

## Запуск программы

Установите Python 3. Откройте папку проекта в VS Code и запустите `main.py` кнопкой Run Python File или командой:

```bash
python main.py
```

На некоторых компьютерах Windows команда может быть:

```powershell
py main.py
```

Программа очень простая. Для выполнения лабораторной достаточно редактировать файл `main.py`; запускать программу после каждого изменения необязательно.

> В методичке указана Visual Studio, но ниже приведены действия для VS Code, которым пользуются участники. Сами операции Git соответствуют заданиям из методички.

# Пошаговое выполнение лабораторной двумя участниками

## Подготовка

1. Объединитесь в пару.
2. Назначьте роли:
   - **Student A** — владелец репозитория.
   - **Student B** — соавтор.
3. Оба участника должны иметь аккаунт GitHub.
4. Оба устанавливают Git и VS Code.
5. Проверьте установку Git в терминале VS Code:

```bash
git --version
```

## Задание 1. Создание локального и удалённого репозитория (Student A)

1. Student A распаковывает проект и открывает папку `Git_Lab_Two_Students_Python` в VS Code.
2. На GitHub создаёт новый репозиторий, например `git-lab-python-two-students`.
3. Можно выбрать Public. При создании репозитория не добавляйте README и `.gitignore`, потому что они уже есть в папке проекта.
4. В VS Code откройте терминал: **Terminal → New Terminal**.
5. Убедитесь, что терминал открыт именно в папке проекта.
6. Выполните команды по очереди, заменив URL на ссылку своего репозитория:

```bash
git init
git add .
git commit -m "Initial commit"
git branch -M main
git remote add origin https://github.com/ВАШ-ЛОГИН/git-lab-python-two-students.git
git push -u origin main
```

7. Если Git попросит авторизацию, войдите в свой GitHub-аккаунт предложенным способом.

**Проверка:** обновите страницу репозитория на GitHub. Там должны появиться `main.py` и `.gitignore`.

## Задание 2. Приглашение соавтора и клонирование (Student A и Student B)

### Student A — приглашает соавтора

1. Откройте свой репозиторий на GitHub.
2. Перейдите в **Settings → Collaborators** (или раздел управления доступом).
3. Нажмите **Add people**.
4. Введите точный GitHub username Student B.
5. Отправьте приглашение.

### Student B — принимает приглашение и клонирует

6. Student B открывает https://github.com/notifications или письмо от GitHub.
7. Находит приглашение и нажимает **Accept invitation**.
8. Получает URL репозитория от Student A. Он выглядит примерно так:

```text
https://github.com/ЛОГИН-A/git-lab-python-two-students.git
```

9. Открывает VS Code и нажимает `Ctrl + Shift + P`.
10. Вводит `Git: Clone` и выбирает эту команду.
11. Вставляет URL репозитория.
12. Выбирает папку на компьютере, куда сохранить проект.
13. После завершения клонирования нажимает **Open**.

Проверка в терминале Student B:

```bash
git remote -v
git branch
```

Удалённый адрес должен вести на репозиторий Student A, а текущая ветка обычно называется `main`.

## Задание 3. Внесение изменений и синхронизация (Student B и Student A)

### Student B — меняет программу и отправляет изменения

1. Откройте `main.py`.
2. Найдите функцию:

```python
def show_student_b_feature():
    print("Функция Student B: изменение успешно добавлено.")
```

3. Измените текст внутри `print`, например:

```python
def show_student_b_feature():
    print("Student B добавил новую функцию в общий проект!")
```

4. Сохраните файл.
5. В терминале выполните:

```bash
git add main.py
git commit -m "Feature from Student B"
git push
```

### Student A — получает изменения

6. В своей локальной копии проекта выполните:

```bash
git pull
```

7. Откройте `main.py` и убедитесь, что изменение Student B появилось.

**Результат:** Student A получил изменение, отправленное Student B.

## Задание 4. Работа с ветками и слияние (Student A)

Все действия этого задания выполняет Student A.

1. Перейдите на `main` и получите последние изменения:

```bash
git switch main
git pull
```

2. Создайте ветку и переключитесь на неё:

```bash
git switch -c new-feature
```

3. В `main.py` найдите функцию `show_greeting()` и измените текст, например:

```python
def show_greeting():
    print("Привет! Это проект двух разработчиков.")
```

4. Сохраните файл и создайте коммит:

```bash
git add main.py
git commit -m "My new feature"
```

5. Вернитесь на ветку `main`:

```bash
git switch main
```

6. Выполните слияние ветки `new-feature` в текущую ветку `main`:

```bash
git merge new-feature
```

7. Отправьте изменения на GitHub:

```bash
git push
```

**Результат:** изменение из `new-feature` вошло в `main`.

## Задание 5. Моделирование и разрешение конфликта слияния (Student A и Student B)

Для конфликта важно, чтобы Student B сначала получил актуальную версию после задания 4, а затем оба участника независимо изменили одну и ту же строку. В следующем порядке конфликт получится предсказуемо.

### Шаг A. Student B обновляет свою копию

1. Student B выполняет:

```bash
git switch main
git pull
```

2. Убедитесь, что в его `main.py` функция `show_greeting()` содержит строку:

```python
print("Привет! Это проект двух разработчиков.")
```

### Шаг B. Student A меняет строку и отправляет коммит

3. Student A в своей копии меняет эту строку на:

```python
print("Привет от Student A!")
```

4. Сохраняет файл и выполняет:

```bash
git add main.py
git commit -m "Greeting from Student A"
git push
```

### Шаг C. Student B меняет ту же строку, не выполняя Pull

5. Важно: Student B пока НЕ выполняет `git pull`.
6. В своей локальной копии он меняет прежнюю строку:

```python
print("Привет! Это проект двух разработчиков.")
```

на:

```python
print("Привет от Student B!")
```

7. Сохраняет файл и создаёт локальный коммит:

```bash
git add main.py
git commit -m "Greeting from Student B"
```

8. Теперь Student B выполняет:

```bash
git pull
```

9. Git должен обнаружить конфликт в `main.py`, потому что Student A и Student B изменили одну и ту же строку по-разному.

### Шаг D. Student B разрешает конфликт

10. Откройте `main.py`. В конфликтующем месте Git покажет блок примерно такого вида:

```text
<<<<<<< HEAD
    print("Привет от Student B!")
=======
    print("Привет от Student A!")
>>>>>>> ...
```

11. Удалите маркеры конфликта `<<<<<<<`, `=======`, `>>>>>>>` и оставьте общий итоговый вариант, например:

```python
def show_greeting():
    print("Привет от Student A и Student B!")
```

12. Сохраните файл.
13. Завершите слияние и отправьте результат:

```bash
git add main.py
git commit -m "Resolve merge conflict"
git push
```

**Результат:** конфликт разрешён, итоговая версия строки находится в общем репозитории GitHub.

Если конфликт не появился, проверьте порядок действий: Student B должен создать локальный коммит со своей версией строки до того, как выполнит `git pull` с изменениями Student A.

# Полезные команды Git

```bash
git status          # показать состояние файлов
git add .           # подготовить все изменения
git add main.py     # подготовить конкретный файл
git commit -m "..." # создать коммит
git push            # отправить коммиты на GitHub
git pull            # получить изменения с GitHub
git branch          # показать ветки
git switch main     # переключиться на main
git switch -c name  # создать ветку и переключиться на неё
git merge name      # слить указанную ветку в текущую
git remote -v       # показать адрес удалённого репозитория
```
